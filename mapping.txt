The goal is to create a convenient admin interface to configuring the mapping of data from the captured HTML to the application's entities/database. The HtmlViewer component should be used as an example of how the source side of the mapping process should be presented.  The user will look at the well-formatted HTML source and identify which element styles/classes/ids the data should be sourced from, and then they will need to choose an application entity property for the destination. These mappings will need to be source URI specific, in that these values will amost certainly differ between the various sites the HTML comes from (LinkedIn, Indeed, other future sites). The desired UX should be that the user finds and selects the value visually in the HTML, rigth-clicks to display a context menu, and then chooses "Map to Entity".  Once this option is chosen, a dialog should be displayed that allows the user to type a custom name and select the entity and property where the value should be mapped.  The URI of the HTML's origin site, selected source value identifier (e.g. CSS class name, element ID, etc.), mapping name, entity name, and entity property name should be stored in the value_mapping table in the database.  At least two new columns "value_entity_property" and "value_site" will need to be added to the schema to support this system. Think about the best way to add this feature, settle on a architectural direction, and then create a full implementation plan for you to refer to.
